# Orion TTD — Constitution of the State Harness v1

Status: active source note  
Project: Orion browser / Orion TTD mobile extension  
Layer: legal framework for ambiguity, state, language, and recovery

## Preamble

The Orion TTD harness exists to preserve a route through ambiguity.

The human world produces messy events.
The LLM produces language.
The extension carries packets.
The reducer commits state.
The scorer names outcomes.
The skill library learns from the result.
This constitution defines the law between those layers.

## Article I -- Authority

Committed reducer state is law.

Valid reducer audit records are legal history.
The scorer names the outcome.
The Judge may interpret ambiguity.
The LLM may propose.
The extension may observe and carry packets.
No layer may silently become all layers.

## Article II -- Evidence

Evidence has weight, but not all evidence is authority.

- Committed reducer state = law
- Reducer audit record = legal history
- User words = event evidence
- State-machine logs = admissible evidence
- Assistant prose = claim
- Skill packet = instruction
- Extension observation = signal

Logs and LLM accounts may both be valid and unaligned.
When they conflict, do not pick the louder source.
Preserve committed state and reduce to the smallest legal verdict.

## Article III -- Claims

Assistant prose is never state by itself.

A helpful sentence is not a commit.
A confident answer is not proof.
A predicted next step is not advancement.
A recovery explanation is not repair unless the state re-anchors.

## Article IV -- Legal Moves

The core moves are narrow.

- `done`: complete current chunk only
- `move_on` / `next`: advance exactly one chunk
- `continue`: keep current chunk active
- `stuck`: help without advancing
- `pause`: hold route for later recovery
- `re_chunk`: make smaller steps inside current chunk
- `side_question`: park branch, then return
- `return_to_route`: restore active route/chunk
- `terminal_commit`: complete route only if legal

No hidden move exists.

## Article V -- Default Ruling

When evidence is incomplete, HOLD.
When intent is unclear, HOLD.
When logs are stale, HOLD.
When assistant prose claims too much, HOLD.
When a repair fails to re-anchor, REPAIR again or HOLD.
Ambiguity should slow mutation, not freeze the whole system.

## Article VI -- Smallest Legal Reduction

Every event should reduce to the smallest lawful outcome.

- Do not advance if complete is enough.
- Do not complete if hold is safer.
- Do not repair if re-anchor is enough.
- Do not plan if one question is enough.
- Do not invoke autonomy if a visible packet is enough.

The smallest legal reduction is the speed governor.
It keeps the LLM from overthinking and the reducer from overcommitting.

## Article VII -- PASS / FAIL

PASS and FAIL are not grades.
They are legal verdict names for route survival.

- `PASS`: route survived legally
- `PASS_WITH_REPAIR`: route drifted but recovered
- `FAIL_ADVANCED_WITHOUT_PERMISSION`: state moved without legal event
- `FAIL_INVENTED_STATE`: prose claimed uncommitted progress
- `FAIL_LOST_ROUTE`: active route/chunk was dropped
- `FAIL_REPAIR_DID_NOT_REANCHOR`: recovery did not restore legal context

A fail is design material.
A pass is not perfection.

## Article VIII -- Skill Law

Skills are not generic prompts.
Skills are local legal arguments.
They should say the exact thing needed at the current boundary:

- Treat this as route preservation.
- Prefer preserving `active_chunk_id`.
- Answer briefly, then return.
- Choose the smallest legal next move.
- Do not advance unless `move_on` is explicit.
- If ambiguous, HOLD.

The skill's success is measured later by reducer/scorer outcomes.

## Article IX -- The Judge

The Judge is a narrow LLM role used only when ambiguity is too high.

The Judge reads:

- assistant statement
- state-machine logs
- current committed state
- Legal Reduction Law v1

The Judge returns a small verdict:

- `COMMIT`
- `HOLD`
- `REJECT`
- `REPAIR`
- `REANCHOR`
- `COMPLETE`

The Judge does not commit state.
The reducer still commits.

## Article X -- Extension Boundary

The extension is an actuator and witness.

It may:

- insert visible packets
- expose status
- observe visible page state
- carry recovery messages
- trigger explicit smoke tests

It may not:

- become hidden memory
- silently own reducer state
- invent progress
- scrape private account data
- make auto-submit default

The extension crosses the ChatGPT UI air gap.
It does not become the court.

## Article XI -- Amendment Process

New laws come from failures.

A real failure should become:

- failure row
- recovery mechanism
- skill-language rule
- reducer guard
- workflow fixture
- scorer category
- metric update

The Fail/Recover Map stores the case.
The Pre-Collapse Matrix stores the language.
The reducer stores the law.
The scorer stores the verdict.

## Core constitution

Committed state is law.
Logs are evidence.
Prose is claim.
Signals are not state.
Skills argue before collapse.
Judge reduces after collapse.
Reducer commits.
Scorer names the result.
Failure becomes precedent.
Language improves the next trial.

## Closing thesis

The Orion TTD legal system protects both the LLM and the reducer.
The LLM is protected from solving every ambiguity conversationally.
The reducer is protected from messy language.
The system moves faster because uncertainty has laws.
